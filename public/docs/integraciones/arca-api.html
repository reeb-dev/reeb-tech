API REST para facturar con ARCA

Registrás el cert del comercio en el servidor, generás un JWT, y emitís con un POST. No montás SOAP a mano en el cliente: eso lo hace el backend.

Introducción

Esta API es la capa REST de una instancia single-tenant (un comercio). Por detrás usa los webservices oficiales WSAA + WSFEv1. Si querés el detalle SOAP, está en SOAP avanzado.

Primeros pasos

  1. Levantá la instancia Backend con ARCA_ENABLED=true, CUIT, paths de cert/key y punto de venta.
  2. Homologá el certificado En ARCA/AFIP (WSASS en homo). PDFs: acá.
  3. Login POST /api/auth/login → guardá el token.
  4. Status GET /api/arca/status debe decir configured.
  5. Emití Creá una venta → POST /api/arca/invoices/{saleId} → leé el CAE.

Base URL

Local http://localhost:8080
Prod https://tu-dominio
Auth Authorization: Bearer <JWT>
POST /api/auth/login público

Obtené el JWT. Para pedir CAE necesitás rol TITULAR.

curl -s -X POST "$BASE/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"email":"titular@comercio.local","password":"tu-password"}'

POST /api/arca/invoices/{saleId} solo TITULAR

Emite (o reusa) el CAE de una venta existente. Body vacío: importes y cliente salen de la venta. Idempotente si ya hay result: "A" con CAE.

Errores frecuentes

CasoQué hacer
401Volvé a login
403Usá usuario TITULAR para emitir
not_configuredCompletá ARCA_* y cert/key
result: "R"Leé observations; revisá RG 5616 en SOAP avanzado

ARCA_ENVHOMO o PROD
