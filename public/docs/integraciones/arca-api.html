Base URL y autenticación

Base URL (local) http://localhost:8080
Base URL (prod) https://tu-dominio
Auth header Authorization: Bearer <JWT> (salvo login)
Content-Type application/json
Cómo obtener el JWT. Primero POST /api/auth/login con email/password de un usuario TITULAR (para pedir CAE). Después pegá el token en Postman → Authorization → Bearer Token.
POST /api/auth/login público

Devuelve el JWT para el resto de llamadas.

Errores habituales

HTTP / casoQué significaQué hacer
401 sin token JWT ausente o inválido Volvé a login
403 rol OPERADOR intentó POST CAE Usá usuario TITULAR
422 / IllegalState “no configurado” Faltan env / cert / key Completá checklist + ARCA_*
Venta no encontrada saleId inexistente Creá la venta primero en el panel/API de ventas
result: "R" o ERROR ARCA rechazó o falló SOAP Leé observations; revisá gaps RG 5616 en la guía

Si querés armar tu propia API

Dos caminos típicos:

Opción A Reusar este contrato REST

Exponé los mismos 3 endpoints en tu backend. El front/Postman no cambia. Adentro seguís haciendo WSAA + WSFE.

Opción B Hablar SOAP directo

Tu servicio firma TRA, cachea TA y llama FECAESolicitar. Usá los PDF y la guía.

Opción C Solo probar contra tu instancia

Importá la colección Postman, seteá baseUrl + login, y pegale a HOMO.

Recordá: ARCA no ofrece REST oficial para CAE. El “estilo Postman” aplica a tu API de producto; hacia AFIP el transporte sigue siendo SOAP/XML.

Colección Postman / Insomnia

Descargá e importá: arca-api.postman_collection.json
Variables: baseUrl (default http://localhost:8080), token (se puede llenar a mano tras el login), saleId.
  1. Postman → Import → elegí el JSON.
  2. Corré Auth → Login y copiá token a la variable de colección (o Authorization).
  3. Corré ARCA → Status.
  4. Poné un saleId real → Request CAE → Get invoice.

Contrato alineado a ArcaController / ArcaInvoiceService de stock-local. Guía SOAP: arca-implementacion.html · PDFs: arca-fuentes.html.
